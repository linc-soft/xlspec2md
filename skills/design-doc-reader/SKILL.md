# 設計書産物の読み方（xlspec2md 産物向け）

## 産物の構成

プロジェクトの `docs/` ディレクトリ（xlspec2md プラットフォームのビルド産物 zip を展開したもの）:

- `docs/common_spec.md` — **プロジェクトの共通仕様書**（固定相対パス。プロジェクト切替はこのファイルの内容差で行われる）
- `<設計書名>/<設計書名>.md` — 各画面設計書の Markdown（主参照文書）
- `<設計書名>/<設計書名>.ir.json` — 構造化中間表現（精确照会用）
- `<設計書名>/<設計書名>.mockup.html` — 座標検証用モックアップ
- `*/media/` — 埋め込み画像（画面イメージのオリジナル貼付け図など）

## 読む順序

1. まず設計書の `.md` を全文読む（数千行でも読み切る。要約しない）
2. 以下の場合は `.ir.json` を併読する:
   - コンポーネントの**正確な座標・サイズ**が必要なとき
   - 項目定義表のセル単位の値（初期値・データソース・備考の全文）を正確に参照するとき
   - Markdown で省略（truncate）されている長い備考を読むとき
3. 画面の視覚的な配置を確認したいときは `mockup.html` を開く

## Markdown セクションの意味

- `## 画面: <名前>` — 1 画面。複数タブ画面がある設計書では `xxタブ` ごとに独立した節がある
- コンポーネント表の列: `種別`（title/group/button/checkbox/sort-or-dropdown/grid-row/text/block）、`x y w h`（ピクセル）、`ソース`（`画面イメージ!E22:N25` という原典セル座標）
- `## 項目定義` — 分類／項目名／モード別 I/O（新規・修正・照会・選択）／必須／初期値／データソース／リスト設定／備考。`I`=入力、`O`=出力
- `## 特記事項` — 並び順・F キーマトリクス等。原文忠実転記（行末の `(C96)` はセル座標）
- `## 機能処理（イベント）` — イベントごとの処理手順。`共通仕様に基づき…` の記述は共通仕様書への参照（下記）
- `## データ更新表` — 対象テーブルと INSERT/UPDATE/DELETE の設定内容（prose 形式のものは手順書き）
- `## 付録: 未構造化シート転記` — 解析器が構造化しなかったシートの原文。要件が混ざっている可能性が高いので**必ず目を通す**
- `## 変換警告` — 解析時の注意。要件欠落のリスクがある

## 座標の解釈

- 原則: **1 列 = 10px、1 行 = 5px**、画面左上が原点 (0,0)
- 実装への換算例（WinForms）: `Label.Location = (x, y); Label.Size = (w, h);` そのまま使える
- `sort-or-dropdown` は ▼/▽（プルダウン）または ▲/△（ソート）のインジケータ。直前の項目に付属するものとして実装する

## 「共通仕様に基づき」の解決ルール

設計書に `共通仕様に基づき、新規処理を実施する` 等の記述があったら:

1. 同じプロジェクトの `docs/common_spec.md` を開く
2. キーワードで該当節を探す:
   - ボタン制御・権限 → `## ５．画面項目制御` / `## １４．権限`
   - フォーカス移動 → `## ４．フォーカス選択・移動`
   - 新規/修正/削除の処理流れ → `## ８．処理の流れ`
   - 一覧 Grid の振る舞い → `## １６．一覧画面仕様`
   - 採番 → `## １０．採番方法`、排他 → `## ９．排他制御`、税計算 → `## １１．金額、消費税計算`
3. 共通仕様に記載がない具体的処理は、共通仕様の**方針**（例: 確認ダイアログの文言パターン、色設定 RGB 値）に沿って実装し、判断した旨をコードコメントに残す

## コード生成上の注意

- 項目定義の `必須=○` には必ず入力チェックを実装する（エラーメッセージは共通仕様のメッセージ規約に従う）
- `データソース`（例: `m担当者.担当者CD`）は DB カラム参照。テーブル名・カラム名をコード上の識別子にそのまま使ってよい
- `リスト設定`（例: `m汎用明細(部署区分)`）はプルダウンの選択肢ソース
- 変換警告に「未構造化シート転記」が含まれる設計書は、付録に要件が含まれている可能性が高い。実装前に付録を確認してから着手すること
